# Operational Reality V1 — Parent Branch Map

Parent branch: `operational-reality-v1`
Base: `immediatelyusable`

Purpose: turn Logistinfra from a project/runtime control system into an operational world-model that continuously protects human attention, pre-positions work, detects degradation, and emits the best executable 10-minute action.

## Priority order

### P0 — daily time freedom
1. `or/cognitimeexec-now`
   - always produce the best executable 10-minute transition;
   - exact surface, action, stop, receipt, fallback;
   - never return vague project-level work.

2. `or/leverage-firewall`
   - classify recurring work as KILL / AUTOMATE / DELEGATE / BATCH / FLOOR / KEEP;
   - eliminate <=1x non-essential human labour;
   - compress mandatory low-leverage work to the minimum reliable floor.

3. `or/predictive-setup`
   - pre-position context, URLs, repos, files, credentials health, prompts, physical/digital materials;
   - only reversible prep before a transition becomes admissible.

### P1 — prevent future waste
4. `or/predictive-maintenance`
   - detect expected-vs-observed degradation before failure;
   - create bounded repair transitions for connectors, CI, credentials, deployments, commitments, proof freshness, capability freshness.

5. `or/life-logistics-floor`
   - university/admin/getting-ready/travel/routine obligations;
   - convert recurring mandatory logistics into defaults, checklists, batching, pre-staging and wake conditions;
   - no duplicate manual tracking.

6. `or/attention-firewall`
   - notifications, inboxes, low-value conversations, feeds and interruptions;
   - wake only on state-changing events, commitments, deadlines, access or high-value relationship signals.

## Global acceptance

At any arbitrary moment the user can ask `NOW` and receive:

- one 0–10 minute executable action;
- why it outranks alternatives;
- exact surface/tool/operator;
- prep status;
- stop condition;
- receipt;
- fallback if blocked;
- interrupt/wake conditions.

The system must also:
- suppress waiting work;
- prevent <=1x non-essential labour from entering the active queue;
- pre-stage likely next work;
- detect maintenance degradation;
- compress mandatory logistics to reliable floors;
- avoid requiring duplicate manual tracking.

## Parent rule

No child may create a new ontology, router, scheduler, memory system, integration framework or UI.

Each child is an independently testable operation pack over the existing runtime.
