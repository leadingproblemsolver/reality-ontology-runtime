# Lineage and System Projections

## 1. Reality Ontology / PRS Layer −1
The substrate question is not “what should we do?” but:

- What entities exist?
- What state are they actually in?
- What evidence permits that assertion?
- Which relationships are valid?
- Which assumptions support our current model?
- Which transitions are legal?
- Who has authority to cause them?
- Did the attempted transition actually occur?
- What is reality now?

This is the root contract.

## 2. Executable State / Constraints / Transitions
The ontology becomes operational when state is not merely represented but used to select a next valid transition.

Canonical form:

`Goal → reconstruct state → identify constraint → choose transition → execute → verify → update reality`

This is the point where ontology becomes an execution system.

## 3. Reality Enforcer
Adds ontological fidelity:

`Decision → Assumptions → Reality Signals → Contradictions → Dependency Re-evaluation → Outcome Fidelity`

Its key job is to prevent stale beliefs from surviving contradictory execution evidence.

## 4. LCE / UCCL / ContextOS
Projects durable reality into bounded working context.

`Corpus → canonicalized evidence → validity graph → Context Packet → action`

The LLM never owns the corpus or canonical state. It receives a bounded projection.

## 5. Logistinfra
Logistinfra is the executable shared kernel.

Minimal primitives:

`Actor, Goal, Object, State, Event, Evidence`  
plus explicit `Relation`, `Execution`, `Attempt`, `Operator`, `Verification`.

Canonical implementation:

`Event/Evidence ledger → state projection → context compiler → planner → permission engine → operator → verification → Reality Store`

Venture-specific systems should supply policies/configuration, not independent architectures.

## 6. Reality Handoff
Reality Handoff is a proof-carrying execution specialization:

`External reality → evidence → deterministic gate → execution contract → human approval → bounded action → independent reread → durable handoff → fresh-agent recovery`

It demonstrates four ontology invariants:

1. evidence precedes mutation;
2. unknown semantics can block execution;
3. verification is independent from action;
4. continuity survives model/session death.

## 7. SignalOps
SignalOps is the operational-exception projection:

`exception → durable case → evidence reconciliation → severity/state → owner → bounded proposed action → authorization → execution/handoff → external reread → settlement`

It is not a separate ontology. It is a domain implementation of the same state/evidence/action/verification loop.

## 8. REF Execution OS
REF projects the ontology into external consequence and proof.

Lower-level control plane:

`CURRENT REALITY → NEXT EVIDENCE EVENT → WORKSTREAM → MEDIUM → HUMAN/AI ACTION → PASS GATE → PROOF → STATE MUTATION → NEXT SPRINT`

Higher-level externalization loop:

`SENSE → EXPOSE → GET PRICED → INTERVENE → VERIFY → EXTRACT → COMPOUND → DEEPEN`

REF adds persistent registries for:

- current state
- workstreams
- artifacts
- leverage
- relationships
- proof
- evidence events
- attempts
- open loops
- platform/account state
- context packets
- logistics
- runs
- decisions
- ICPs/triggers
- deployables
- content
- experiments

## 9. External Proof / Market Projection
Internal work is not equivalent to external reality.

The truth ladder is explicit:

`DISCUSSED → DECIDED → PREPARED → IMPLEMENTED → TESTED → DEPLOYED → EXPOSED → EXTERNALLY_USED → REUSED → ADOPTED → PAID → OUTCOME_PRODUCING`

Market observations mutate the model:

`signal → actor → trigger → pain/workflow → intervention → response/null result → evidence → updated ICP/priority/product`

This is the same ontology loop with the market as the observed system.

## 10. Relationship / Human-Capital Projection
A relationship is persistent state, not a sequence of isolated messages.

Typical state:

`UNKNOWN → CONTACTED → RESPONDED → SUBSTANTIVE_EXCHANGE → ARTIFACT_SHARED → USED → RETURNED → COLLABORATING → COMMERCIAL`

A known person is never reset to a cold prospect merely because a new campaign starts.

## 11. Operator Family
Small artifacts are enforcement operators, not separate ontologies:

- **RealityLatch** — blocks progression when required reality/evidence conditions are unsatisfied.
- **TraceCrumb** — preserves reconstruction evidence/provenance.
- **Reality Handoff** — serializes evidence + decision + bounded action + verification + recoverable state.
- **DecisionKillSwitch** — invalidates dependent decisions when governing assumptions die.
- **Proof Guardian / claim gate** — blocks evidence-state inflation.

## 12. Final architectural relation
Reality Ontology is not “inside” Logistinfra as one optional module.

It is the substrate contract that Logistinfra makes executable.

Logistinfra is the motor + nervous system.
Reality Store is durable state.
ContextOS/LCE is bounded working memory.
Reality Enforcer is validity control.
Reality Handoff is proof-carrying mutation + recovery.
SignalOps is a verticalized operational case model.
REF is the external consequence / proof / compounding projection.
