# Primary Reputation Community — n8n

## Decision

Use the **n8n community + n8n GitHub ecosystem** as the first concentrated reputation surface for applied automation/agent reliability work.

This is not because n8n is the deepest possible infrastructure community. It is because it currently combines:

- a large active automation user base;
- a public community forum;
- a dedicated Jobs category with paid project demand;
- open-source contribution routes;
- workflow-template contribution;
- custom/community node publishing;
- real operators with broken workflows every day.

That makes it unusually strong for **short time-to-real-user, short time-to-paid work, and short feedback loops**.

## Community rule

Do not arrive with Logistinfra as an abstract framework.

Enter through real n8n failure modes:

- duplicate external side effects;
- ambiguous execution after timeout;
- missing resume state;
- brittle long-running workflows;
- human approval boundaries;
- webhook/retry idempotency;
- stale context in AI workflows;
- workflow handoff/debugging;
- external verification after mutation.

## Reputation ladder

1. Reproduce one real community problem precisely.
2. Publish the smallest working fix/diagnostic.
3. Help the user verify it.
4. Write the reusable explanation/template.
5. Repeat across 3–5 real cases.
6. Only then propose a deeper reusable node/library/tool.
7. Convert proven patterns into upstream issues/PRs where n8n maintainers explicitly want them.
8. Use the resulting receipts for paid Jobs-category work and automation-engineer applications.

## Contribution constraints

n8n's current contribution guidance makes pre-coordination important:
- bug fixes should have an issue with reproduction;
- features/enhancements should start in the forum;
- core changes require contact first;
- new core nodes are not accepted unless requested;
- small focused PRs with tests are preferred.

Therefore reputation work should start with:
- community debugging;
- issue reproduction;
- docs where useful;
- workflow templates;
- independent community nodes only when the use case repeats;
- pre-coordinated core PRs.

## Employment conversion

Primary target roles:
- automation engineer;
- AI automation engineer;
- integration engineer;
- solutions engineer;
- workflow engineer;
- technical implementation / developer experience;
- n8n specialist/consultant.

Primary paid surface:
the n8n community Jobs category.

Do not mass-post "for hire".
First build 3–5 externally verified technical receipts in public threads, then answer paid requests where those receipts are directly relevant.

## Secondary protocol surface

MCP is the deeper protocol/community alignment for Logistinfra's long-term architecture, especially enterprise readiness, authorization, audit trails and agent communication.

But use MCP as the **second** reputation layer after n8n gives us fast operational receipts.
